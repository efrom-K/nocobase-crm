# nocobase-crm

**EN:** A rental-contracts CRM built on top of [NocoBase](https://www.nocobase.com/) (Docker Compose + PostgreSQL), written for a Russian-language
office, so the UI is in Russian. Contracts move through three stages — *Forming* (6-step approval by role) → *Active* → *Completed* — and are shown in a
registry with modal contract cards. Highlights: multiple extra contacts per contract, bank name and correspondent account auto-filled from the Russian
Central Bank BIK directory (weekly sync from the official ED807 file), read-only view of completed contracts, per-contract chat, files and addenda.
The custom UI is a set of NocoBase JS blocks (`src/`), the DB schema (no data) and a page snapshot are in `db/`, and `docs/flow-engine-notes.md`
collects hard-won notes about the NocoBase flow-engine. MIT licensed.

CRM для учёта арендных договоров на базе [NocoBase](https://www.nocobase.com/) (Docker Compose + PostgreSQL).
Главный экран — **«Реестр договоров»** с тремя вкладками по жизненному циклу договора:

**Формирующиеся** → (оформление по 6 этапам с ролями) → **Активные** → («Завершить договор») → **Архив**

## Что умеет

- Карточка договора в модальном окне: данные договора, помещение, расчёты, контрагент, примечания, файлы, доп. соглашения.
- Оформление нового договора по этапам (заявка → объявление → согласование → подписание → оплата → финал); подтверждать этап может только своя роль (Отдел аренды / Юр. отдел / Бухгалтерия).
- **Личные черновики** (коллекция `draft_contracts`, отдельная вкладка «Черновики», не нативная таблица — карточный список): и «Создать договор», и «Срочный договор» теперь сначала создают черновик, видимый только автору (фильтр по `created_by_id` на клиенте — коллекция без ACL-оверрайда, чтобы не наступить на баг NocoBase с рендером колонок, см. `docs/flow-engine-notes.md`). Запись в базе появляется только после первого реально заполненного поля — случайный клик по кнопке ничего не создаёт. Кнопка «Опубликовать → Формирующиеся» переносит договор в общий процесс (этап 1) тем же механизмом, что и обычная публикация. Черновики без активности дольше 3 суток удаляются сами (`scripts/purge_stale_drafts.py`, ночной cron) — активность = правка любого поля (`last_activity_at`) или запись в истории (файл/контакт/график цены/переход этапа).
- **Срочный договор**: кнопка рядом с «Создать договор» — все поля всех этапов сразу в одной форме, без ролевого гейтинга и обязательных полей (валидация формата данных при этом действует так же, как везде). Теперь ведёт в личный черновик (см. выше), не сразу в «Формирующиеся». В истории — отдельная пометка о создании «одной формой».
- **Добавление участника в существующий чат** (мессенджер, панель «Информация» → «Участники»): кнопка «+ Добавить участника» — личный чат 1:1 при добавлении третьего человека автоматически становится группой.
- **Защита от случайного клика на «Создать договор»/«Срочный договор»**: если карточку закрыли, не введя ни одного значения (и не добавив сотрудников/файлов), черновик в «Формирующихся» тихо удаляется сам — не остаётся мусорной строкой.
- **Договоры, требующие внимания, — всегда наверху списка** (пока пользователь сам не отсортировал колонку явно): строки с непрочитанными уведомлениями поднимаются в начало таблицы. Открытие карточки договора сразу отмечает связанные уведомления прочитанными и снимает подсветку, не дожидаясь, пока их откроют в колокольчике.
- Чат по договору, сотрудники по договору, уведомления.
- **Дополнительные контакты** (`contract_contacts`): у договора может быть сколько угодно контактных лиц — ФИО, должность, телефон, почта. Основной контакт остаётся в полях договора (по нему работают колонки таблицы), остальные — отдельным списком. При смене статуса договора контакты переезжают вместе с ним.
- **Автоподстановка банка по БИК**: при вводе 9 цифр БИК подставляются название банка и корр. счёт из справочника ЦБ РФ (`bik_directory`, обновляется раз в неделю из ED807). Если БИК не найден — подсказка, поля можно заполнить вручную.
- **Строгий ввод и нормализация**: во всех полях карточек нельзя ввести неверный формат. Числовые поля принимают только цифры (суммы и площадь — с запятой и до 2 знаков), ИНН проверяется по контрольной сумме (10/12 цифр), счета — 20 цифр и контрольный ключ относительно БИК, телефон приводится к `+7XXXXXXXXXX`, почта — к нижнему регистру и проверяется, ФИО — только буквы, ссылки — только `http(s)://` (без схемы добавляется `https://`) и кликабельны в просмотре, в заметках и в чате. Сохранение (и переход на следующий этап оформления) блокируется, пока в изменённом поле ошибка.
- **Живая проверка БИК**: по мере ввода показывается «ещё N цифр» → «✓ БИК корректен · банк · город» (банк и корр. счёт подставляются и блокируются) или «✗ Некорректный БИК». Проверяется и при открытии формы.
- **Дата расторжения и напоминания** (с 24.09.2026 дата окончания договора не используется): «Дата расторжения договора» в блоке «Данные по договору» необязательная, её заполняют у уже действующего договора. Как только её заполнили, статус договора становится «Требует внимания» («Проблему» не понижает). `scripts/expiry_reminders.py` (cron, раз в день) шлёт прикреплённым сотрудникам уведомления за 90 / 60 / 30 дней до расторжения, каждый порог один раз на конкретную дату (журнал `contract_reminders_log`). В карточке рядом с датой — бейдж «до расторжения N дней».
- **История изменений**: в каждой карточке (формирующийся / активный / завершённый) есть раздел «История изменений»: кто, когда и что изменил («поле: было → стало»), переходы по этапам, смена статуса, контакты, файлы, доп. соглашения, сотрудники. Серия правок одного поля тем же автором за 10 минут схлопывается в одну запись, откат правки удаляет запись. История переезжает вместе с договором при смене статуса. Пишется из интерфейса карточек (правки мимо карточек, например SQL или API, в историю не попадают).
- **Уведомления через штатный колокольчик NocoBase** (без самодельного): сообщения разложены по каналам-блокам — «Сроки договоров», «Статус договоров», «Назначения», «Чат по договору», «Личные сообщения». Слева каналы с последним сообщением и счётчиком непрочитанных, фильтры «Все / Непрочитанные / Прочитано», «Отметить все как прочитанные», ссылка «Вид» открывает нужную карточку договора или чат. Схема доставки: интерфейс и скрипты пишут строку в очередь (`contract_notifications` с полем `channel`, `chat_notifications`), а два workflow отправляют её штатным менеджером уведомлений — поэтому сотрудникам не нужны права на `messages:send`, а доставка идёт в реальном времени. Настройка с нуля: `scripts/setup_notifications.py`.
- **Только непрочитанное:** вкладки «Все / Непрочитанные / Прочитано» скрыты CSS-правилом, а фильтр «Непрочитанные» включается автоматически (оба лежат в начале `src/contract-modals.js`; для других страниц добавьте их в их JS-блок). При этом фильтре штатный список сразу убирает сообщение после прочтения. Прочитанное физически чистится ночью скриптом `scripts/purge_read_notifications.sh` (cron); удалять сразу при прочтении нельзя — штатный клиент оставляет на колокольчике кружок с «1», если канал внезапно опустел.
- **Русский интерфейс:** язык системы ru-RU, единственный разрешённый (`enabledLanguages = ["ru-RU"]`: иначе английский, когда-то выбранный в браузере, перебивает системный язык); недостающие переводы штатных плагинов и названия полей/ролей добавлены (`scripts/localize_ru.py`, `scripts/ru/`). Патч плагинов лежит внутри контейнера и после обновления образа NocoBase его нужно применить заново.
- **Связанные поля (мягкий автопересчёт):** АП = ставка за 1 кв.м. × площадь, ЭС = ставка ЭС × площадь; если ставка пустая, а сумма и площадь есть, ставка считается обратно. Пересчёт трогает только пустые значения или те, что раньше совпадали с расчётом: то, что правили вручную, не затирается. Под полями АП/ЭС подсказка «По ставке × площади = … — подставить».
- **График цены аренды** (`contract_price_periods`): на каждый промежуток времени своя цена; цена задаётся фиксированной суммой или за 1 кв.м. и относится к месяцу, неделе, дню или году (месяцы считаются по календарю, неполные — пропорционально дням). Периоды не могут пересекаться; показываются итог по графику, текущая цена, разрывы в сроке договора. Цена действующего сегодня периода **применяется сама**: сразу при сохранении/удалении периода в карточке и каждую ночь скриптом `scripts/apply_price_schedule.py` (когда наступает новый период, ставка и АП меняются, изменение пишется в историю от имени «Система», сотрудникам договора и ролям отдела аренды/юристов приходит уведомление; ручные правки внутри периода не затираются). Кнопки «Рассчитать «Сумму договора» по графику» и «Применить цену периода на сегодня». Периоды переезжают с договором (формирующийся → активный → архив) и попадают в историю изменений.
- **Подсветка договоров с уведомлениями:** если по договору есть непрочитанное уведомление, его строка в таблице подсвечивается (оранжевый фон, пульсирующая полоска слева, подсказка с текстом), а на вкладках («Активные», «Формирующиеся», «Архив») появляется счётчик таких договоров. Подсветка уходит, когда сообщение прочитано в колокольчике. Берётся из ссылки `?open=<тип>:<id>` в сообщении (`src/registry-tabs.js`).
- **Статусы-светофоры (только активные договоры):** столбцы «Статус договора» (В порядке / Требует внимания / Проблема) и «Статус оплаты» (Оплачено / Ожидает оплаты / Просрочка) — цветные бейджи с подписью внутри, в стиле кнопок «Завершить»/«Удалить». Выбираются вручную: прямо в ячейке таблицы (штатная быстрая правка, карандаш при наведении) или в блоке «Статусы» карточки; в истории изменений видны подписи. Значения хранятся с числовым префиксом (`1_problem`, `2_attention`, `3_ok`, `1_overdue`, `2_waiting`, `3_paid`), поэтому сортировка по столбцу ставит проблемные первыми. У формирующихся договоров и в архиве этих столбцов нет. Список статусов и цвета задаются в описании полей (`uiSchema.enum`) и в `STATUS_OPTIONS` (`src/contract-modals.js`).
- **Личные столбцы таблиц:** кнопка «⚙ Столбцы» над таблицей позволяет каждому пользователю выбрать, какие столбцы показывать, и расставить их порядок стрелками; есть «Сбросить» и «Одинаково для всех вкладок». Настройка личная (таблица `user_table_settings`, дублируется в localStorage) и применяется только в браузере пользователя — в общие настройки страницы ничего не пишется. Запасные столбцы (окончание, арендная плата, обеспечительный платёж, ИНН) скрыты по умолчанию и включаются там же. Реализовано через flow-engine: `setHidden` и `sortIndex` столбцов (`src/registry-tabs.js`).
- **Блок «Характеристики и расчёты»** (бывший «Цена и платежи»; блок характеристик помещения убран): площадь, арендная плата и эксплуатационный сбор (за 1 квадратный метр и в месяц), обеспечительный платёж, комментарий (`calc_comment`; у формирующихся — комментарий этапа «Оплата счетов», переносится при переводе в «Активные»). **Сумма договора = арендная плата + эксплуатационный сбор** в месяц, считается сама и вручную не правится. Отметки о выставленных и оплаченных первых счетах убраны. Все деньги и площади выводятся ровно до сотых (65,00), подписи полей — без сокращений и скобок (`scripts/setup_calc_block.py`).
- **Настоящие типы данных:** даты (`date`) и суммы/площадь (`double`) хранятся как даты и числа, а не текст — сортировка по дате и по цене работает корректно (раньше `01.09.2025` шла перед `13.08.2025`, а `980` после `90`). Разовая миграция с сохранением непонятных значений в примечания: `db/migrations/001_typed_columns.sql`. Поиск по строке работает по текстовым полям.
- **Сортировка** по всем колонкам во всех трёх таблицах реестра (Активные, Формирующиеся, Архив).
- Просмотр договоров в **архиве** (только чтение: все блоки, контакты, файлы, доп. соглашения, чат, сотрудники).

## Почта (вкладка «Почта»)

Веб-почта внутри NocoBase с единым входом: сотрудник входит только в NocoBase, почта открывается сама.

- `mail-service/` — небольшой сервис на Node.js (imapflow, nodemailer, mailparser) в Docker, порт 8096 на том же сервере.
  Кто пришёл, он узнаёт по токену сессии NocoBase (`auth:check`), ящик = email пользователя NocoBase.
  Пароль от ящика сотрудник вводит один раз в самой вкладке; хранится зашифрованным (AES-256-GCM, ключ `MAIL_KEY` в `.env` сервиса) в `data/creds.json`.
  Если пароль сменили — вкладка один раз попросит новый. Пилот ограничивается списком `MAIL_USERS` в `.env`.
- `src/mail.js` — интерфейс (JS-блок страницы «Почта»): папки со счётчиками, список писем с превью, флажки, поиск, чтение письма
  (текст в изолированном iframe без скриптов, картинки из интернета — по кнопке), ответ / ответить всем / переслать с вложениями,
  новое письмо с подсказками адресов (сотрудники и «Контактные данные» договоров), вложения до 25 МБ, черновики, массовые действия.
- Выкладка сервиса — вручную: `rsync -a --exclude node_modules --exclude data --exclude .env mail-service/ server:nb_mail/ && ssh server 'cd nb_mail && sudo docker compose up -d --build'`.
  Интерфейс выкладывается как обычный блок (`deploy/blocks.json`).
- Страницу и доступ к ней создавать только через API NocoBase (`desktopRoutes:create`, `roles/<роль>/desktopRoutes:add|remove`):
  прямые записи в `desktopRoutes`/`rolesDesktopRoutes` сервер не видит до перезапуска (кэш), а `desktopRoutes:create` сам открывает страницу всем ролям.

## Запуск

```bash
cp .env.example .env        # заполнить APP_KEY и DB_PASSWORD
docker compose up -d        # NocoBase на http://localhost:13000
```

Дальше в NocoBase: создать коллекции по `db/schema.sql` (либо загрузить схему в БД и добавить коллекции через
«Менеджер источников данных» / API `collections:create`), собрать страницу реестра по снимку из `db/`.
Автоматического импорта снимка страницы в репозитории нет — он нужен как справка и для ручного восстановления.

### Выкладка изменений в JS

```bash
scripts/deploy_block.py ie2yqcr89cg src/contract-modals.js --ssh user@server   # или без --ssh для локального docker
```
Код блока подхватывается при перезагрузке страницы, рестарт не нужен. Перед правкой блока сделайте бэкап `flowModels`.
Соответствие `uid` → файл: см. `$file` в `db/registry-page.flowModels.json`.

### Справочник БИК

```bash
python3 scripts/bik_load.py        # разовая загрузка (нужен docker и доступ к cbr.ru)
# cron, раз в неделю:
0 4 * * 1 /usr/bin/python3 /path/to/scripts/bik_load.py >> /var/log/bik_load.log 2>&1
```
Источник — официальный файл ЦБ `https://www.cbr.ru/s/newbik` (ED807). Если разбор дал меньше 1000 записей, скрипт ничего не трогает.

## Модель данных (кратко)

- `forming_contracts`, `rental_contracts` (активные), `completed_contracts` — одна и та же схема полей; договор физически переезжает между таблицами при смене статуса.
- `contract_contacts`, `contract_addendums`, `contract_history`, `contract_chat_messages`, `contract_notifications` — «боковые» данные, привязка по паре (`contract_type` ∈ `forming|active|completed`, `contract_ref_id`).
- `bik_directory` — справочник банков (`bik` уникален).

## Безопасность

В репозитории нет данных арендаторов и секретов. Дампы базы с данными в git не добавлять (в `.gitignore` есть шаблоны).

## Пайплайн

Проверки — GitHub Actions (`.github/workflows/ci.yml`, `scripts/ci_checks.py`), выкладка — агент на сервере, который вытягивает зелёные коммиты `main` и обновляет JS-блоки. Подробно: [`docs/deploy.md`](docs/deploy.md).
